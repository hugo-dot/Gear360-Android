# Observations SM-R210 / Galaxy A05

Extraits des sorties ADB observees dans la session du 10/11 septembre 2026.
Ce document est un releve partiel, PAS une capture HCI ni un logcat complet.

## Provenance de l'analyse

- Manager 1.5.00.1: SHA256
  `96C53A4F7D80D53D82428D525FF85C6836326D885476A5C6B6AA5F273955FA28`.
- SAccessoryService 3.1.93.90325 extrait de ses assets: SHA256
  `6DCA93BAC5D0F76A59C0176A3748E982E208A3BDAC9426C88414C5C9112CAE03`.
- Le DEX confirme `BTMProviderService.onPeerFound -> establishConnection ->
  requestServiceConnection`, meme si le XML declare provider.
- `SAServiceDescriptionParser.checkRole`: provider=0, consumer=1.
- `SACapabilityUtils.formServiceCapabilityParams`: version encodee major<<8 | minor.
- `SACapexFrameUtils.composeCapabilityDiscoveryResponseMessage`: checksum
  present pour queryType 2 et 3, absent pour 1.

Les sources decompilees restent dans `reverse-engineering/`, hors APK et archive source.

## Paquets reels

Premiere Peer Description: longueur 0x0033, puis paquet device 5, version 2.1.
Les noms Sband+/Shealth sont ceux effectivement emis par ce firmware, pas un
modele deduit du nom Bluetooth.

```text
00 33 05 02 01 02 01 02 00 0F FA AA F0 AA 03 FE FF FF 02 00 0A 01
53 62 61 6E 64 2B 3B 53 41 4D 53 55 4E 47 3B 53 68 65 61 6C 74 68
3B 2F 53 62 61 6E 64 2B 3B
```

L'authentification WSM a confirme le chemin protocole 1 (challenge 70 octets,
reponse 102, confirmation 35). Le resultat JNI positif signifie succes.

La reponse d'ouverture du service de capacites etait statut 0, session 1:

```text
09-11 01:22:39.963 I/G360-SAP(10320): CAPEX service accepted session=1; legacy query sent
09-11 01:22:39.971 I/G360-SAP-FRAME(10320): RX session=1 type=DATA crc=ENABLED len=7 HEX=01 02 00 00 00 00 00
09-11 01:22:40.118 I/G360-SAP(10320): legacy CAPEX response len=54
09-11 01:22:40.192 I/G360-SAP(10320): CAPEX query queryType=2 len=25
```

La seconde requete vise exactement le profil Gear360:

```text
00 1B 0B 40 00 04 01 02 00 00 00 00 01
2F 73 79 73 74 65 6D 2F 44 49 5F 33 36 30 5F 32 44 3B 10 DD
```

Decoupage: longueur 0x001b, CRC longueur 0x0b40, header SAP session1 `00 04`,
payload CAPEX `01 02 ...`, CRC payload `10 DD`.

L'annonce emise a cet instant contenait encore role=1, donc consumer: ceci ne
correspondait pas au provider du XML officiel. La correction role=0 et la
demande sortante native sont posterieures a cet essai.
